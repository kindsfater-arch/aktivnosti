# Сервис «Активности»: решения и план

Инструкция по запуску — в [README.md](README.md).

## Принятые решения (20.10.2026)

| Вопрос | Решение |
|---|---|
| Структура журнала | Колонки A–L основного файла не меняются. Справа добавляются M «Сумма сделки» и служебные колонки N–S: ID, источник потенциала, автор, создано, изменено, удалено. Одна строка — одна активность |
| Канал поступления | Кампания продаж · Пиратка · Полевой обход · Личное привлечение · Другое |
| Статус | В работе · Недозвон · Отказ · Блокировка 115-ФЗ · Договор подписан · Договор запущен · Выполнено расширение |
| Сумма сделки | обязательна для статусов «Договор подписан», «Договор запущен», «Выполнено расширение» (тип статуса «Сделка») |
| Вид активности | Звонок · Встреча · Сообщение |
| Дата активности | обязательна, формат даты (проверяется в интерфейсе, на сервере и в самой таблице) |
| Комментарий | обязателен, не короче 10 символов — суть активности |
| Потенциал оборота в мес | сумма `vol` по всем строкам ИНН в последнем PS, то есть весь оборот клиента у конкурентов. Ручная правка сохраняется и при импорте не перезаписывается |
| Оборот Сбера | из PL_xx (колонка «Оборот» = US + NON-US; на сентябре сверено с US_09 по всем 7 173 ИНН — совпадает). Если PL нет — US_xx, обе суммы. В журнал не пишется, показывается только в карточке ИНН |
| Названия ЮЛ | ФНС без ключа. Найденные один раз ИНН кэшируются, повторно не ищутся. DaData — запасной вариант, если задан ключ |
| Вход | по персональной ссылке. Администратор выдаёт и перевыпускает ссылки |
| Видимость | сотрудник видит свои активности и тех, кого открыл администратор. НО и администратор видят всё |
| Отчёты | НО, администратор и пользователи с флагом «Отчёты». Форматы: Excel, PDF, PowerPoint. НО и администратор выгружают ещё и сводный файл целиком |

## Готово

- Сервер на Apps Script: API, роли, проверки, импорт PS/PL/US, ФНС, отчёты, выгрузки.
- Веб-интерфейс: план, активности, сделки, лиды PS, отчёты, админка; адаптирован под телефон.
- Автодеплой с GitHub (clasp и, по желанию, GitHub Pages).

## Дальше

1. Первый запуск по README: clasp, `setup()`, развёртывание, репозиторий на GitHub.
2. Завести пользователей: ФИО, тип (МПП/МПС/МРГК/НУ), НО. Раздать ссылки.
3. Проверить на реальных данных: импорт PS_08 целиком (~8 МБ), ввод активностей с телефона, выгрузку отчётов.
4. По желанию: рассылка отчётов по расписанию (день, неделя, месяц) и контроль факта после «Договор запущен» — рост оборота в Сбере по следующим PL-файлам.
